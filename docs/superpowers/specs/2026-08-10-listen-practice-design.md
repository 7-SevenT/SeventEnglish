# 听力上传与听写练习设计 — SeventEnglish

日期：2026-08-10

## 背景与目标

SeventEnglish 是一个个人英语阅读与听力练习工具（React 19 + Vite + Cloudflare Workers 全栈 SPA，D1 + R2 存储）。听力模块当前能力：

- **上传**：`BooksAdmin` 中一次仅上传**单个**音频文件，且需手动填写 word（否则取文件名）。
- **听写**：`Practice` 中是"听一题填一题交一题"的单题流程，一次只显示一道题。

本次目标是改造两个页面，解决三个痛点：

1. **多文件上传**：一次选择多个音频文件批量上传。
2. **符号预填**：答案含 `$ 184`、`19 °C`、`40%`、`500,000 tons` 等符号时，听写中自动显示符号（货币符号、%、°C），用户无需输入；仅需输入核心数字、英文单位词（`tons km guests metres cm`）以及 `.` `/` `-` 符号；大数字在输入过程中自动补千分位逗号。
3. **分轮次循环听写**：一页显示该轮所有空位，播放列表（小圆点）+ 整体开始/暂停，每音频间隔 5 秒，播放到哪个空位哪个高亮，全部播完统一提交判对错；错词进入下一轮（随机打乱），循环直至全对完成一大轮。
4. **只通过音频文件名取单词**：上传不再提供 word 手动输入框，也不允许上传非音频文件。

## 数据来源

单词答案来自**上传音频的文件名**（去扩展名后作为答案词，即当前 `/api/words` 缺省行为）。符号预填从前端解析答案字符串得出，不在数据库新增字段。后端 `/api/words` 无需改动。

## 核心模块：答案解析引擎 `src/lib/answer.ts`

纯函数模块，可独立单元测试。把答案字符串（来自音频文件名）解析为"预填部分 + 用户输入部分"。

### 返回结构

```ts
export interface ParsedAnswer {
  prefix: string; // 预填前缀：$ £ €（只读显示）
  suffix: string; // 预填后缀：% °C 及必要前一空格（只读显示）
  digits: string; // 纯数字段（含原始千分位逗号的答案，用于实时格式化提示）
  rest: string;   // 需要用户输入的其余部分：英文单位词、字母、. / - 符号
}
```

额外导出常量与工具：

```ts
export const PREFILL_SYMBOLS = [...];           // 前缀 $ £ €；后缀 % °C
export function parseAnswer(word: string): ParsedAnswer;
export function formatThousands(rawDigits: string): string; // 输入过程实时补千分位
export function normalizeCompare(input: string): string;    // 判定时规范化（去空格/大小写/千分位）
export function isCorrect(userInput: string, parsed: ParsedAnswer): boolean;
```

### 解析规则

1. **前缀预填**：答案开头匹配 `$` `£` `€` 之一 → 提取为 `prefix`，其余为剩余串。
2. **后缀预填**：剩余串结尾为 `%` 或 `°C`，连同其前一格空格 → 提取为 `suffix`（如 `19 °C` → suffix=` °C`）。
3. **去除前缀后缀后的剩余串**再拆为 `digits`（数字与千分位逗号部分）+ `rest`（字母、`.`、`/`、`-` 等非数字字符片段，原样保留）。

示例映射：

| 答案 | prefix | suffix | digits | rest | 用户需输入 |
|---|---|---|---|---|---|
| `$184` | `$` | – | `184` | – | `184` |
| `19 °C` | – | ` °C` | `19` | – | `19` |
| `40%` | – | `%` | `40` | – | `40` |
| `500,000 tons` | – | – | `500,000` | `tons` | `500000 tons`（逗号实时补） |
| `£8.50` | `£` | – | `8.50` | – | `8.50`（点自输） |
| `2/3` | – | – | – | `2/3` | `2/3`（斜杠自输） |
| `1882–1883` | – | – | – | `1882–1883` | `1882–1883`（横线自输） |

### 千分位实时格式化

用户输入纯数字（对应 `digits` 中去除逗号的数字串）时，随输入实时插入千分位逗号，显示与答案数字一致。

- 答案 `500,000` → 用户输入 `500000` → 输入过程中实时显示 `5,000` → `50,000` → `500,000`。
- 判断对错时忽略逗号。

### 判定 `isCorrect`

将用户输入与答案规范化比较：

- 忽略大小写、两端/中间多余空格。
- 忽略千分位逗号与货币/符号差异 —— 由于符号已预填为只读，比较的核心是 `digits + rest`。

规范化：把用户输入与答案分别处理后判定是否含逗号差异。具体实现保证：`500,000` 与 `500000`、`19 °C` 与 `19`（用户不必输 `°C`）判为正确。

## 上传改造：`BooksAdmin.tsx`

- 文件选择框加 `multiple`，一次选多个音频。
- **移除 word 手动输入框**。仅允许音频文件（校验 `accept="audio/*"` + 前端扩展名/类型过滤），拒绝文档等其他文件。
- 批量上传：对选中的每个文件调用 `uploadWord(unitId, file)`（word 省略，后端取文件名），逐个 `/api/words`，全部完成后刷新单词列表。
- 上传中显示进度（已上传 x/n），出错时提示并继续剩余文件。

后端 `/api/words` 已支持缺省 word 取文件名，无需改动。

## 听写练习重构：`Practice.tsx`

### 页面结构（分轮次）

```
进入 → 加载单元全部单词
   │
   ▼
第 1 轮（全部词，随机顺序）
   │  播放列表 + 空位 → 全部播完 → 点"提交判断对错"
   ▼
有错词？ ──是──▶ 第 2 轮（仅错词，重新随机）→ ……
   │
   └─否─▶ 本单元练习完成（一大轮达成）
           显示：总轮数、本轮正确数、总用时
```

### 轮次数据模型

```ts
interface RoundItem {
  parsed: ParsedAnswer;   // 每题答案解析
  wordId: number;
  audioUrl: string;
  answer: string;         // 原始答案串
}
```

- `currentPool`: 当前轮题目（数组，进入轮次时 `shuffle` 随机打乱）。
- 提交判定后，把错的题收集为 `wrongPool`，若非空则作为下一轮 `currentPool`（再次 shuffle）；为空则完成。
- 累计 `totalRounds`、`totalSeconds`。

### 播放列表 UI

- 每个词一个小圆点，多排排列（flex-wrap）。圆点状态：未播 / 当前播放（高亮）/ 已播。
- **整体开始 / 暂停**按钮。
- 自动顺序播放：当前题音频结束后**间隔 5 秒**再播下一题。
- **点击某圆点复听**该词（可选；若想重播当前词，点击当前）。复听不影响自动序列，仅单次播放。
- 与空位联动：当前播放到哪个词，对应空位高亮（`isActive`）。

### 空位 UI

- 一页渲染当前轮所有空位（`RoundItem` 列表）。
- 每个空位三部分：**左前缀预填**（只读，如 `$`）→ **输入框** → **右后缀预填**（只读，如 ` °C`）。`digits` 输入实时补千分位，`rest` 作为单独输入框（多个 `rest` 片段则按顺序合并展示，简化为一个 `rest` 输入框）。
- 输入框随播放高亮当前项。
- 用户可随意点任意空位、随时编辑（不限于当前播放项），但逻辑上按播放序列走。

> 简化决策：为减少组件复杂度，`digits`（数字）用一个输入框，`rest`（字母/符号）用一个输入框，二者并排。用户分别填写。判定时拼接 + 规范化比较。

### 提交判定

- 全部播完后启用"提交判断对错"按钮。
- 逐题用 `isCorrect` 判断，正确空位标绿、错误标红并显示正确答案。
- 把错误题收集进错词池，进入下一轮。

## 设计为隔离与可测

- `src/lib/answer.ts` 为纯函数、无 DOM 依赖，配套 `src/lib/answer.test.ts`（vitest），覆盖示例表和边界（无符号、多符号、纯数字、斜杠/横线答案）。
- 组件层 `Practice.tsx` / `BooksAdmin.tsx` 只消费 `answer.ts` 的解析结果，不内嵌解析逻辑。
- 播放调度逻辑在 `Practice.tsx` 内一个自定义 hook 或内联 `useEffect`，与渲染解耦。

## 样式

在既有 `src/styles.css` 追加类：

- `.listen-dots`（小圆点容器，flex-wrap）、`.listen-dot`（未播）、`.listen-dot--active`（高亮）、`.listen-dot--done`（已播）。
- `.listen-empty` / `.listen-empty--active`（空位高亮）。
- `.listen-prefill`（预填符号，灰置只读）。
- `.listen-word-line`（每题一排：前缀+数字输入+rest输入+后缀）。
- 完成页统计块。

## 范围边界（非目标）

- 不改后端 / 数据库 / `/api/words` 逻辑。
- 不实现"从 Markdown 单词列表文件自动导入关联"（仅文件名取答案）。
- 不停表统计历史、进度持久化（本轮完成即本次会话结束，不存库）。
- 不引入新 npm 依赖（沿用 Vite + React + vitest）。

## 实现方式

1. 新增 `src/lib/answer.ts` + `answer.test.ts`。
2. 改造 `src/pages/admin/BooksAdmin.tsx`（多文件上传）。
3. 重构 `src/pages/Practice.tsx`（分轮听写）。
4. `src/styles.css` 追加样式。
5. 校验：`npm test`（新增单测）+ `npm run build` 通过。
