# SeventEnglish 管理工作台重构设计

- 日期：2026-08-12
- 状态：已获用户批准（设计阶段）
- 范围：管理后台全链路

## 一、目标

将现有管理后台重构为现代化的统一工作台，固定包含三个一级功能：

1. 文章
2. 听写
3. AI模型

本轮重点解决两类录入体验问题：

- 文章新增从单一表单升级为右侧抽屉快速录入，支持 Markdown/TXT 导入、实时预览和当天日期默认值。
- 听写资源从多层展开、逐文件上传升级为可恢复的批量导入工作流，支持文件名自动解析答案、逐项修正、进度展示和失败重试。

用户侧阅读、听力学习页面本轮只保持 API 和路由兼容，不进行全面换肤或业务重构。

## 二、已确认的产品决策

### 2.1 工作台布局

采用“左侧导航 + 主工作区 + 右侧抽屉”布局：

- 左侧一级导航：文章、听写、AI模型、返回学习端。
- 主区域展示模块标题、说明、统计摘要、搜索/筛选工具栏和资源列表。
- 新增、编辑和导入都在右侧抽屉中完成，不离开当前列表。
- 桌面端抽屉宽约 440–520px；窄屏下退化为全屏面板。
- 页面内通知替代浏览器 `alert`。
- 删除操作使用现有现代确认对话框。

### 2.2 文章录入

- 入口：文章列表右上角“新建文章”。
- 抽屉字段：标题、发布日期、正文来源。
- 发布日期默认当天。
- 正文支持直接粘贴，或拖入/选择 Markdown、TXT 文件。
- 抽屉内提供简洁预览。
- 标题、日期和正文在字段附近显示校验错误。
- 保存成功后自动触发现有异步 AI 分析流程。
- 本轮不引入独立草稿状态。
- 编辑文章复用同一抽屉，关闭有未保存内容时要求确认。

### 2.3 听写批量导入

- 入口：听写模块的“导入听写音频”。
- 在同一工作流中先选择单词书和单元，再选择音频。
- 支持一次拖入多个 MP3、WAV、M4A、OGG 等音频文件。
- 默认使用去掉扩展名的文件名作为答案。
- 导入队列允许逐行修改答案。
- 每个文件拥有独立的等待、上传中、成功、失败状态和进度。
- 单个文件失败不阻塞其他文件；失败项目可单独重试。
- 上传完成后统一刷新目标单元的单词列表。
- 关闭抽屉不会清除已完成的上传结果。
- 创建单词书、创建单元和查看词汇明细都通过抽屉或明细面板完成，避免当前多层 `fieldset` 嵌套。

### 2.4 AI模型

- AI 模型成为独立一级模块。
- 配置字段：OpenAI 兼容的 Base URL、API Key、模型名。
- 支持通过 `GET /models` 拉取模型列表。
- 模型既可从列表选择，也可手动输入，兼容上游列表不完整的情况。
- API Key 脱敏展示；留空保存时保留已有 Key；只有输入新 Key 才覆盖。
- 支持保存配置和测试连接。
- 文章分析从 D1 配置读取，不再依赖 `OPENAI_*` 环境变量。
- 不执行旧 `OPENAI_*` 配置自动迁移，由管理员上线后在后台重新配置。

## 三、信息架构与路由

```text
/admin
├── /admin/articles       文章
├── /admin/dictation      听写
└── /admin/ai-model       AI模型
```

现有 `/admin/books` 保留兼容并重定向到 `/admin/dictation`。现有文章、书籍、单元、单词 API 继续兼容，必要时增加批量导入所需的管理 API。

### 3.1 AdminLayout

`AdminLayout` 负责工作台外壳，不负责具体资源 CRUD：

- 响应式侧边栏。
- 当前路由高亮。
- 模块标题和主操作区域。
- 抽屉、通知和确认对话框的挂载层。
- 返回 `/read` 或学习端的入口。

### 3.2 文章模块

主区域支持：

- 文章总数、最近文章和 AI 状态摘要。
- 标题搜索。
- 日期筛选。
- AI 状态筛选。
- 列表行显示标题、发布日期、内容预览、AI 状态、更新时间。
- 编辑、重新分析和删除操作。

### 3.3 听写模块

主区域采用“单词书卡片 → 单元列表”的层级结构：

- 单词书卡片显示书名、描述、单元数和音频数量。
- 单击展开单元列表。
- 单元行显示单词数量和导入状态。
- 单词明细通过抽屉或明细面板查看。
- 主操作为“新建单词书”和“导入听写音频”。

### 3.4 AI模型模块

展示配置卡片与连接状态：

- 当前 Base URL。
- 当前模型。
- API Key 是否已配置。
- 已连接、未配置、连接失败状态。
- 最近测试时间。
- 拉取模型、测试连接、保存配置操作。


复用现有 `ConfirmDialog`、API 客户端、全局 CSS token、按钮和表单基础样式。

### 4.1 文章组件

- `ArticlesAdmin`：列表加载、搜索筛选、通知、抽屉开关和资源操作。
- `ArticleEditorDrawer`：表单状态、文件解析、预览、校验、保存和未保存确认。

### 4.2 听写组件

- `DictationAdmin`：单词书/单元列表、创建和删除操作。
- `DictationImportDrawer`：位置选择、文件选择、答案修正和导入控制。
- `UploadQueue`：上传任务状态、进度、并发控制、失败重试和完成刷新。

### 4.3 AI组件

- `AiModelAdmin`：读取脱敏配置、编辑、保存、测试连接和模型列表刷新。
- 加密、配置读取和上游请求留在 Worker 侧，前端不实现任何密钥解密逻辑。

## 五、后端与数据流

### 5.1 AI管理 API

新增管理 API：

```text
GET  /api/admin/ai-model
PUT  /api/admin/ai-model
POST /api/admin/ai-model/models
POST /api/admin/ai-model/test
```

约定：

- 所有接口受现有认证中间件保护。
- `/models` 使用保存中的配置，或使用本次请求提供的未保存配置进行测试拉取。
- `/test` 验证 Base URL 和 API Key 的可连接性，并返回选定模型是否出现在上游列表；自定义模型未出现在列表时显示提醒而不直接判定连接失败。
- 失败响应只返回用户可理解的错误，不返回 Key、Authorization 头或完整上游响应体。
- 所有上游请求使用 OpenAI 兼容路径：`/models` 和 `/chat/completions`。

### 5.2 AI配置存储

继续使用现有 `settings` 表，使用键 `ai_model_config`。值为 JSON：

```json
{
  "base_url": "https://example.com/v1",
  "model": "gpt-4o-mini",
  "api_key": {
    "version": 1,
    "iv": "base64url",
    "ciphertext": "base64url"
  },
  "updated_at": "2026-08-12T00:00:00Z"
}
```

API Key 使用 Worker Web Crypto 的 AES-GCM 加密：

- 每次加密生成新的随机 IV。
- D1 仅保存版本、IV 和密文。
- 解密只发生在 Worker 内存中。
- GET 接口只返回 `has_api_key` 等脱敏信息。
- 加密密钥缺失或无法解密时，配置接口返回明确的配置错误，不能静默使用明文。

### 5.3 文章分析

文章保存后：

1. 写入文章数据。
2. 检查 D1 中是否存在可用 AI 配置。
3. 已配置时沿用现有后台异步分析机制。
4. 未配置时文章仍保存，状态显示为“待配置 AI”。
5. 配置完成后可从文章列表触发重新分析。

## 六、环境变量与认证

最终使用：

```env
LOGIN=sevent
SESSION_SECRET=一段随机高强度会话签名密钥
ENCRYPTION_KEY=一段随机高强度加密密钥
```

约定：

- Worker 从 `LOGIN` 读取登录密码。
- `sevent` 是当前部署配置中的值，不硬编码到源码。
- `SESSION_SECRET` 继续用于无状态会话 cookie 的 HMAC 签名。
- 删除 `SITE_PASSWORD`、`OPENAI_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_MODEL` 的运行时依赖。
- 更新 `.dev.vars.example`、README 和认证/AI 测试。
- `SESSION_SECRET` 与 `ENCRYPTION_KEY` 必须由部署环境提供，不能提交到仓库。

## 七、错误处理与可访问性

### 7.1 错误处理

- 表单错误显示在字段附近。
- 页面级错误使用统一通知组件。
- 删除使用确认对话框。
- 上传错误保留失败文件和重试按钮。
- 重复提交通过提交中状态和按钮禁用防止。
- AI 未配置不阻塞文章保存。
- 上游错误统一转换为安全、可理解的提示。
- 不使用浏览器 `alert`。

### 7.2 响应式与可访问性

- 桌面端为侧边栏 + 主区 + 抽屉。
- 移动端侧边栏可折叠，抽屉全屏显示。
- 所有抽屉可通过关闭按钮、Escape 和遮罩关闭。
- 有未保存内容时关闭前确认。
- 按钮、输入框和状态徽章保留清晰的键盘焦点。
- 上传队列和异步分析状态使用可读的文本，不只依赖颜色。
- 继续使用项目现有 CSS token，不引入额外 UI 依赖。

## 九、非目标与约束

本轮不做：

- 用户侧阅读页面全面换肤。
- 用户侧听力练习逻辑重写。
- 多 AI 配置档案或模型切换历史。
- 独立草稿、发布审批和权限角色系统。
- 音频资源跨单元复用资源库。
- CSV/表格导入。
- 新增第三方 UI 框架。

实现时必须保留工作区中与阅读标注/分析相关的现有未提交改动，不回滚或覆盖与本设计无关的文件。
